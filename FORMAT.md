# Keepsafe vault file format ("KPSF")

This document is the contract between every module that reads or writes a
vault file. It is owned at project level; changes require a format version
bump and a tested migration path.

## Design rules

1. Every byte of the file, header included, is authenticated. A tampered
   header is detected and refused, never obeyed.
2. All KDF parameters live in the header so they can be raised later without
   breaking older readers of the same major version.
3. The nonce is unique per encryption with overwhelming probability: it is
   generated by the crypto library's own secure random generator at
   192 bits (XChaCha20-Poly1305-IETF via libsodium's nacl.secret.Aead).
   Collision odds for n encryptions
   are below n^2 / 2^193; for a personal vault this is practically zero.
   Uniqueness is additionally asserted empirically in the test suite by
   collecting nonces across many encryptions.
4. No plaintext, key material, or passphrase is ever written to disk outside
   the authenticated ciphertext.

## Layout, version 1

All integers little-endian. Offsets are exact.

```
offset  size  field
0       4     magic            b"KPSF" (0x46 53 50 4b on disk)
4       4     format_version   u32, currently 1
8       1     kdf_type         u8, 1 = Argon2id
9       32    salt             random 32 bytes from CSPRNG
41      4     kdf_memory_kib   u32, memory cost in KiB (default 65536)
45      4     kdf_iterations   u32, time cost (default 3)
49      4     kdf_parallelism  u32, lanes (default 4)
53      24    nonce            random 24 bytes from CSPRNG, per encryption
77      8     payload_len      u64, length of ciphertext+tag that follows
85      ...   payload          XChaCha20-Poly1305-IETF ciphertext
                             (plaintext + 16-byte Poly1305 tag)
```

Header = bytes [0, 85). The AEAD call passes the entire header as associated
data (libsodium's native additional-data input), so the authentication tag
covers header plus payload together.

Payload plaintext is UTF-8 JSON:

```json
{
  "format": 1,
  "entries": {
    "web/github": {
      "name": "web/github",
      "username": "...",
      "secret": "...",
      "url": "...",
      "notes": "...",
      "tags": ["dev"],
      "created": "2026-08-22T12:00:00+00:00",
      "updated": "2026-08-22T12:00:00+00:00",
      "fields": [{"key": "recovery", "value": "...", "secret": true}]
    }
  }
}
```

- Entries are keyed by full path (`folder/subfolder/name`, forward slashes).
  Folders have no separate existence; they are implied by paths.
- Timestamps are ISO 8601 UTC with offset.
- Writers serialize with `sort_keys=True` so identical content yields
  identical bytes before encryption.

## KDF parameters

Defaults shipped in v1 (policy constants in `keepsafe/crypto.py`):

| param        | default | policy minimum | hard maximum (untrusted header) |
|--------------|---------|----------------|---------------------------------|
| memory_kib   | 65536   | 65536 (64 MiB) | 2097152 (2 GiB)                 |
| iterations   | 3       | 3              | 32                              |
| parallelism  | 4       | 1              | 64                              |
| salt         | 32 B    | 16 B           | fixed at 32 B                   |
| key length   | 32 B    | fixed          | fixed                           |

Parameters arrive from the plaintext header before authentication succeeds,
so readers enforce the hard maximum and refuse absurd values with a clean
error instead of attempting a multi-gigabyte derivation. Passphrases given
as text are Unicode-normalized to NFKC then UTF-8 encoded before hashing;
NFC and NFD input therefore derive the same key.

A test asserts the shipped defaults meet or exceed the policy minimums so
they cannot be silently lowered. Tests that need speed pass small parameters
as explicit function arguments through clearly marked seams; production code
paths always use stored header values or these defaults.

## Versioning and migration

- Readers must refuse files whose `format_version` they do not know, with a
  message that says the file was written by a newer version. This check
  happens before any decryption work.
- Opening a vault always migrates nothing silently: migration happens only
  via an explicit user-invoked command (`rekey`), which writes a new file
  after an automatic backup.
- Every released format version gets fixture vaults generated by
  `tools/make_fixtures.py` (committed) and tests proving later versions open
  them byte-for-byte identically at the entry level.

## Failure semantics

Any of the following produce one generic unlock failure: wrong passphrase,
tampered/corrupt header, truncated file, bad tag, ciphertext shorter than
the authentication tag. The CLI must not attempt
to distinguish them further, because distinguishing helps an attacker more
than a user. The message names both possibilities (see DESIGN.md error
taxonomy). The only pre-decryption failures allowed to be specific are:
file missing, magic mismatch, unknown format version.
